## Recent Learnings (2026-01-13)

**CRITICAL: No Emojis in Rhino Code ✅**
- Problem: Using emojis in Python code causes `UnicodeEncodeError` on Windows (cp1252 encoding limitation)
- Rule: NEVER use emojis in code that runs in Rhino or outputs to console
- Use instead: Plain text markers like `[OK]`, `[ERROR]`, `[INFO]`, `[WARN]`
- Applies to: All Python scripts, RhinoScript code, print statements, error messages
- Example: `print("[OK] Materials created")` NOT `print("✅ Materials created")`
- See: Common patterns in AGENTS.md "Behavioral Guidelines"

**Multi-Door Grasshopper Automation - Enhanced ✅**
- Created: `dev/create_7_doors.py` - Automated creation of 7 doors with WebSocket monitoring
- Key Learnings:
  1. **All Prompts Must Be Captured**: Rahmentuer_UD5.gh requires 4 prompts (Lichthoehe, Lichtbreite, Get Point, Bandseite) - missing Bandseite caused failures
  2. **WebSocket Event Monitoring**: Essential to see ALL prompts Rhino asks - use monitoring script first
  3. **Timeout Handling**: If no events for 5 seconds, cancel and retry (script is fast, shouldn't hang)
  4. **Retry Logic**: Up to 3 retries per door improves robustness
  5. **Random vs Alternating**: Both patterns work - random for variety, alternating for predictable patterns
- Files: `dev/create_7_doors.py`, `dev/monitor_door_script.py`
- See: `docs/learnings/grasshopper-automation.md` for patterns

**Material Assignment to Layers - RESOLVED ✅**
- Fixed: Objects appearing white despite materials assigned to layers
- Root causes: Missing MaterialSource setting, incorrect Modify() parameters, incomplete material creation
- Solution: Set MaterialSource=MaterialFromLayer, use layer.Index (int) for Modify(), add to both doc.Materials and doc.RenderMaterials
- See: `docs/learnings/material-assignment.md` for complete guide with best practices
